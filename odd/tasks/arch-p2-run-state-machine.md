# Architecture phase 2: Run state machine

Objective: the run is a declared state machine in which every step names its id, phase, guard and failure class, returns a closed outcome (`next`, `goto(state)` or `end(RunEnd)`), every failure goes through one policy table, sub-loops are states with counters, and `finalizeRun` is the only place that persists, publishes, learns and prunes. Source: `docs/architecture-remediation.md` (plan phase 2; closes M1-M9, L6). Baseline: HEAD `17a24923` (2026-10-25).
Branch: `arch/remediation` (owner rule: one branch, no PR split; worktree `.claude/worktrees/arch-remediation`). Delivery: work-unit commits (about 400 authored lines each, advisory); a task whose Risk names a high-risk item ships as its own commit. Runner: `node --import ./test-setup.mjs --import tsx --test <file>` under Node v24.11.0. Phase gate: one transition test per sub-loop, and the P0.4 end-reason table unchanged except the rows a P2.5 commit names (S9).

Do not confuse this document with `odd/tasks/run-state-machine.md`: that is the predecessor feature that produced today's linear step list (RunState, RunContext, step table, runner). Read it once for the decisions it records (strangler order, behavior-preserving, `RunQaResult` and `RunOutcome` unchanged); this phase builds on that code and must not leave a trace of the previous form (S0).

## Specs

- **S0: Constraints on every task of this phase.**
  - **Golden rule.** Project-agnostic and model-agnostic. No app-specific branch in `src/` or `qa-engine/`. Nothing names the model in use. Fixes are root-cause and transversal (AGENTS.md, "Golden rule").
  - **Final state only.** No code, name, comment, test title or doc may refer to a previous form of the architecture or to a resource that no longer exists (owner, L1). Comments describe the final state, not the process. Transitional shims introduced by a strangler step (S2a) are deleted by the task that closes the migration and a test or `rg` check proves it.
  - **Invariants near this phase.** Security boundary (an untrusted git tree is always a security refusal, S5b); the sequential queue; the explicit no-op (`skipped` with `noop` and zero specs stays valid, silence stays `E-NO-DECISION`/`E-STEP-BUDGET`/`E-TIME-BUDGET`); loud integration errors (never swallow an error into an empty result: a fail-open is logged and named in the policy table); sanitization of data leaving the system (notes and logs reach Issues and prompts only through the existing sanitizers, unchanged); the execution launcher and the confined reader (no new `child_process` import, no bare `fs` on agent-influenced paths); the agent stays read-only on watched repos (only the deterministic `finalizeRun` publishes).
  - **Names from earlier phases.** P1.1 renamed `src/server/rewritten-engine-factory.ts` to `src/server/run-engine-factory.ts` (`createRunEngineFactory`, `buildCompositionConfig`, tests `run-engine-factory.*.test.ts`) and `rewritten-orchestrator.adapter.ts` to `run-pipeline.adapter.ts` (`RunPipelineAdapter`); its S1c renamed `LegacyRunOutcome`/`toLegacyRunOutcome` to `StoredRunOutcome`/`toStoredRunOutcome` and `roleForLegacyAgent` to `roleForAgentName`; P1.2 renamed `bridges/` to `adapters/` (`wireBridges` is `wireAdapters`); P1.3 renamed the coordination event kind `router` to `lead-decision`. This document uses the final names: a HEAD `path:line` is only a locator, the symbol is the reference, and T0 re-resolves both.
  - **Governance-sensitive changes ship alone.** A change to a path in `PROTECTED_PATHS` (`src/server/merge-guard.ts:21`), a security invariant or agent write authority is its own commit. S5b changes a security refusal: own commit.   - **Test discipline** (`docs/testing-standards.md`). RED before the fix, then GREEN, then refactor. Test through the public seam (`RunQaUseCase.run`, `runFlow`, `finalizeRun`, `classifyFailure`, `guarded`), never a private helper or exact prompt wording. One RED test per rule. One test pinning the previous behavior of every existing end reason or option that shares the changed code (the P0.4 table does this for ends). Differential check: run the P0.4 table and `run-qa.use-case.test.ts` against a copy of the base commit in a `mktemp -d` directory outside the worktree, then against the change, and compare verdict, persisted/published/learned flags, error class and note. Import production constants (`ERROR_CLASS`, `MAX_STATIC_FIX_ROUNDS`, `MAX_REVIEW_TURNS`) instead of re-typing literals.
  - **Mutation anchors.** `scripts/mutate.ts` pins each preset by a symbol or a `mutation-scope:begin/end` marker pair in the source (`path.ts@name`), never by line (P0.2 landed). The `carry-forward` preset names markers in `phases/generation-services.ts`, `phases/generate.steps.ts`, `phases/execute.steps.ts`, `phases/fix-loop.steps.ts`, `phases/coverage.steps.ts` and `phases/review.steps.ts` (`rg -n "run-flow" scripts/mutate.ts`).
