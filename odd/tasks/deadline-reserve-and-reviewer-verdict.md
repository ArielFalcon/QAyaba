# Deadline reserve and reviewer verdict

Objective: a spent purpose share must never end a run that still had time, the deadline must not hold time for a phase the run will not enter, and "the reviewer did not answer" must stop being recorded as a rejection.
Branch: `fix/deadline-reserve-and-reviewer-verdict` (worktree `../qayaba-fix-deadline`, from main `e1c526aa`). Delivery: ask-on-risk. Runner: `node --import ./test-setup.mjs --import tsx --test` (Node v24).

## Specs

- **S1** (fix acceptance owns its timeout): `fixLoopAcceptance.accept` catches `AllotmentSpentError`, records the fix-loop limit (`allotment`, purpose `fix`) and ends the round as skipped, so the run goes on and closes with its failing verdict. A `RunDeadlineExceededError` still ends the run (the run itself is spent). Source: `engine/src/contexts/run-orchestration/application/run-flow/phases/fix-loop.steps.ts`, `fix-loop.aggregate.ts`.
- **S2** (the reserve knows what will not run): a purpose whose phases this run cannot enter is not reserved. The run tells the deadline when it knows (no green bytes ⇒ coverage; context mode; a cross-repo run), and `reserveAfter` subtracts that purpose. No phase name, no change fact: the input is the run's own state. Source: `engine/src/contexts/run-orchestration/domain/run-deadline.ts`, `shared-kernel/deadline-purpose.ts`, `application/run-flow/phases/{execute,coverage}.steps.ts`.
- **S3** (three-valued verdict): the reviewer signal distinguishes `approved`, `rejected` and **no verdict**. `review-port.adapter.unavailable` stops returning `approved: false`; the type makes the third state representable and forces every reader to handle it. Source: `engine/src/contexts/generation/infrastructure/adapters/review-port.adapter.ts`, `run-orchestration/application/run-flow/phases/review.steps.ts`, the signal's type in `run-orchestration/domain`.
- **S4** (readers): every reader of the reviewer verdict handles no-verdict without inventing one — the `review_verdict` grader returns no score (`engine/src/contexts/evaluation/domain/graders.ts`), the coordination `reviewOutcome` says `n/a` (`decided-end.ts`), the publish/decision path reads only a real verdict (`publish-decision.service.ts`, `run-decision.service.ts`), and `finalize-run.ts` stops hard-coding `reviewerApproved: true` for `skip` and `terminal` ends.
- **S5** (tests, one per rule, through the public seam): an acceptance whose purpose is spent does not end the run and the run closes with the failing verdict; a run with no green bytes does not reserve coverage time; a reviewer that did not answer stores no verdict and the grader scores nothing; an approved and a rejected verdict keep today's values.
- **S6** (unchanged elsewhere): a run with a real verdict keeps the same `approved`/`rejected` values; a purpose the run reaches is allotted what the purposes after it leave, because its own share never stood in its way, so a red-then-green run measures with the same formula and with the time its fix loop did not borrow; `npm test`, `typecheck`, `arch:check` and `contract:check` stay green (the last only if the wire moves).
