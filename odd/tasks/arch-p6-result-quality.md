# Architecture phase 6: Result quality

Objective: every failure the harness reports says whether it is in the change's reach, change-coverage is reported per use-case candidate with the reason when it is unknown, fault injection corrupts only the operations the change reaches and is calibrated before any app moves toward enforce, and the use-case-coverage evaluation measures detection of the relevant use cases on top of the candidates. Source: `docs/architecture-remediation.md` (plan phase 6; closes C8–C10). Baseline: HEAD `209dca5f` (2026-10-25).
Branch: `fix/failure-observation-conflict` (owner rule: one branch, no PR split). Delivery: work-unit commits (about 400 authored lines each, advisory); a task whose Risk names a high-risk item ships as its own commit. Runner: `node --import ./test-setup.mjs --import tsx --test <file>` under Node v24.11.0. Phase gate: an Issue states whether its failure is in the change's reach (S5).
