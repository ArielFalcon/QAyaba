# prompt-integrity

Objective: every role's prompt states only what is true for its own turn, is built from the one section registry, and gives each flow author the slice of the change it must exercise, so generated suites catch defects instead of asserting render smoke.
Branch: main (integration worktree `../qayaba-integrate`, branch `integrate/prompt-integrity`). Delivery: work-unit commits, ff-merge to main. Test runner: `LC_ALL=C node --import ./test-setup.mjs --import tsx --test <file>` (Node v24); full gate per AGENTS.md.

## Specs

Source: the prompt audit of runs `run-ed28973-mvqc7x8j-2da31df4` and `run-ed28973-mvqd9fda-955d5933`, the root-cause plan (engram `plan/prompt-findings-root-cause`) and the prompt-management research (L4). Paths are evidence at HEAD 82e1eaeb.

- **S1 Reviewer spec block (finding 2).** The reviewer's spec list holds each spec file once, deduplicated by the kernel spec path (`shared-kernel/spec-path.ts`), never per test case (`review-port.adapter.ts:71-72`). Whether spec contents are inline or must be read is ONE typed outcome computed once (`deriveReviewerContext`); the instruction line (`reviewer-sections.ts:63`, "The spec contents are provided in this prompt — no need to read files.") and the specs section (`review-render.ts:69`, "( spec contents exceed 40000 bytes — read each file with the read tool )") both render from it, so they can never contradict. The instruction's reference to inline contents is a prompt-contract artifact reference (R13), linted. A matrix cell covers the over-cap reviewer.
- **S2 Lead review states the orchestrator's facts as the orchestrator's (findings 3, 5).** A sidekick answer the reader could not read is rendered as an orchestrator fact, never under "Sidekick says / Sidekick concerns" (`delegation-reading.ts:92-116` → `lead-review.ts:102-103`). A `run_spec` failure is presented as the last failure only when its ledger sha256 equals the current spec bytes read through the confined reader; otherwise it is labelled as a failure of earlier bytes (`lead-sidekicks.ts:827`, `lead-review.ts:82-92`; also `orchestratorFacts` and `verifyInstruction`). A flow whose spec bytes did not change since the lead last saw them in this session is not re-sent: its line states it is unchanged since review turn N with its sha and line count (assumption pending Q5: a short digest line is always sent). The orchestrator-facts-decide rule is unchanged.
- **S3 Shared seeds (finding 1b, data side of 1).** A graph walk cut by its budget marks every seed a hub (`reach-proof.ts:123-131`), so pages reached only through hubs get no code seed. A candidate whose page a hub reaches carries that hub's `file::symbol` and changed range as `sharedSeeds` (optional, additive on `UseCaseCandidate`); a hub alone still never creates a candidate and `seeds` keeps its meaning (coverage ownership, per-candidate coverage, gap routing, causal label unchanged). `dropRefusal` checks a `no-observable-change` drop against `seeds ∪ sharedSeeds` code files (`plan-coverage.ts:54-58`); a contradicted drop takes the existing one re-ask, then `dropsContradicted` path, never an infra-error. The lead's candidate line names shared seeds with kind, added lines and pages reached. The `qayaba.change.candidates` span counts shared seeds.
- **S4 Brief from the change slice (findings 1, 6).** Each flow author's brief carries one section naming the change it must exercise: per file path, language-registry kind, added lines and origin (map-link, graph, shared); symbols with ranges; hunks ordered code first, then hunks holding a changed decision, then diff order, every owned hunk preloaded while the brief fits the author's window by the S12 fit rule (no fixed byte budget, L12-L14), what does not fit degrading to references named as `file:range` in the S12 order. The duplicated proofs section goes. Known facts are filtered to the flow's own pages and say where they were read. A section with no items is not rendered. The author contract no longer asks for `evidence`, `validation` or `assumptions` (Q2, L9): nothing reads them, and the validation-plan machinery they serve is removed with them (`DelegationBrief.validationPlan` is never set by any caller, so the pushback check over it never runs; the `## Validation plan` section is always `(none)`). The internal `evidence` of orchestrator facts stays.
- **S5 Reviewer slice (finding 4; Q1 answered in L7).** On a run with a plan, the reviewer is given, instead of the whole commit diff: the change slices of the flows under review; the full changed-file list (path, language-registry kind, added/removed lines); IN FULL, every part of the diff no flow's slice holds, under a heading that says it is assigned to no flow; and the untaken arms it already receives. When nothing is assigned, the result is the whole diff, so the reviewer never sees less than the change. Runs with no plan (code, manual, complete, exhaustive) keep the whole diff. Measured in the next campaign: reviewer prompt bytes and steps down; missing cases and verified corrections not down.
- **S6 Static decision listing per language (finding 1, phase 2).** Blocked on Q3.
- **S7 One prompt engine (research point 1).** Every role prompt (lead plan, lead review, lead correction, explore, flow-author brief, generator, reviewer) is assembled from registered section definitions (`PromptSectionDef`, `prompt-sections.ts`) through the assembler, so sizes, hashes, budgets and the prompt-contract lint apply to all of them. A lint/arch rule fails when a role prompt is built outside the registry. The prompt-contract matrix covers the coordination prompts.
- **S8 Brief contract (research point 2).** A delegation brief is linted for its contract: an objective, the return shape, the boundary (what it may write and must not do) and the tools it holds; each is present exactly once and states only what the turn grants.
- **S9 Stable prefix (research point 3).** Within each role's prompt, sections that do not vary per run come first and run-varying facts last; no timestamp, run id or unordered-key serialization in the stable prefix. A test proves the stable prefix is byte-identical across two runs with different facts. Cache-read tokens per turn are reported per role.
- **S10 Every section earns its place (research point 4).** Each registered section declares the observed failure or contract it exists for (a short reason, optionally a run id); the lint fails on a section with none. Removing a section is measured by a campaign.

- **S11 Change map and slice (grounding).** Kernel `ChangeMap`: every changed file once (path, language-registry kind, added/removed lines, test/generated/low-relevance flag, the candidate ids it seeds); never cut. Kernel `ChangeSlice` per flow: every hunk overlapping a seed or shared seed of the flow's candidates (a whole-file seed takes every hunk of its file), each hunk once with its candidate ids, ranked (code, other kinds, styles, then diff order; a decision rank filled by S6), the rest as references `path:start-end (+a −r, kind, why)`; app test files, lockfiles, generated files and maps are only referenced; `unassignedOf(map, slices)` gives the diff no slice holds (the whole diff when there are no slices).
- **S12 Context window and fit.** A per-run `ContextWindowPort` (role → live window from the runtime's `modelWindows`, built in the composition root; qa-engine never imports src/; fakes in tests) and a `ContextBudget`: a prompt fits when prompt + expected working room <= window; the working room is estimated from telemetry (per-step session growth x the role's usual steps), never a fixed share. Degradation order (L13). Unknown window: fail open (preload all owned content, no split) and record `windowUnknown`. The model catalog inside qa-engine (`model-window-catalog.ts`, names models, invents a 32K fallback) and the module-global live windows are removed; the lead plan prompt is fitted to the lead's own window, not the author's.
- **S13 Derived flow capacity.** `maxFlows` stops being a fixed 6 that rejects a whole plan: capacity derives from `maxParallel` and the run's remaining time (`parallel x floor((remaining - reserve) / flowBudgetMs)`), with an optional per-app ceiling for cost. `run_spec` and authenticated-browser budgets are granted per flow with a useful minimum (bounded by DEV time), instead of a per-run total split until a flow gets 0 (`NO_CALLS`). The plan section states the capacity; candidate lines carry each candidate's owned-slice size so the lead groups well in the first plan.
- **S14 One plan amendment turn.** Unresolved candidates, contradicted drops and oversize flows are asked of the lead in ONE follow-up turn, not separate re-asks.
- **S15 Lead planning section from the map.** The lead's plan prompt carries the `ChangeMap` and the ranked hunks that fit its own window (S12), with the rest as references; no blind 50 KB diff cut. The `## Commit diff` heading stays (judges read it back).

Decisions applied by owner authorization (L14), each the recommendation given: Q-a yes (S13); Q-b no cost budget yet, measure cost per run by tier; Q-c per-flow grants (S13); Q-d fail open (S12); Q-e delete the in-engine model catalog (S12); Q-f the reviewer's unassigned remainder that does not fit goes as references, not a split review; Q-g no byte budget (L13); Q-h S5 re-baselined: the reviewer prompt grows on large changes because nothing is cut silently; the measure is "no truncation, test files named", plus missing cases and verified corrections not down; Q3 static decision listing declared per language in the language registry, JS/TS first, a language with none states nothing; Q5 the unchanged-spec digest line is always sent (as implemented). Q4 (truncated-walk hits creating candidates) is not changed.
