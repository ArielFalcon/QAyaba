# Architecture phase 3: Hexagonal re-cut

Objective: every engine context has one public surface and one build function, ports are one file each and owned by the context that serves them, the kernel holds only what several contexts share, no engine/shell twin remains, and a machine rule keeps all of it true. Source: `docs/architecture-remediation.md` (plan phase 3; closes H2, H3, H4, H5, H6, H7, H8, H9, H10, D9, N4, N6). Baseline: HEAD `209dca5f` (2026-10-25).
Branch: `fix/failure-observation-conflict` (owner rule: one branch, no PR split). Delivery: work-unit commits (about 400 authored lines each, advisory; a pure move counts as zero authored lines); a task whose Risk names a high-risk item ships as its own commit. Runner: `node --import ./test-setup.mjs --import tsx --test <file>` under Node v24.11.0. Phase gate: the P0.3 baseline reaches zero, so `npm run arch:check` reports 0 violations of the hexagonal rules with an empty baseline, and a context-graph test proves the contexts are acyclic (S9).

### Target layout of every context

```
<context>/domain/                    pure; imports only the kernel and its own domain
<context>/application/index.ts       the only file other contexts may import (ports, use cases, public types)
<context>/application/ports/<name>.port.ts      one port per file; index.ts re-exports, never declares
<context>/application/<use-case>.ts
<context>/infrastructure/adapters/   implements this context's ports (P1.2 name)
<context>/composition/build-<context>.ts        build<Context>(deps): wires adapters to use cases; imported only by the shell root
```

Rules (S9 enforces them): `domain/` imports nothing outward; `application/` imports `domain/`, its own `ports/`, the kernel, and other contexts only through their `application/index.ts`; `infrastructure/` imports `application/ports/`, `domain/`, the kernel and `shared-infrastructure/`; `composition/` is imported only from `src/`; no module cycles; no context-level cycles. A port is owned by the context that serves it: the provider declares the port and ships the adapter; the consumer imports the port from the provider's `application/index.ts`. That is what removes the context cycle: `LearningPort` and `CurriculumPort` are declared by `cross-run-learning`, not by the orchestrator.
