# route-availability

Objective: qayaba tells a route that is unavailable by design from one unavailable by error, walks the code graph without a cut that loses seeds, and stops cutting grounding and prompt sections with fixed caps; then the run's duration is explained and reduced.
Branch: main (parallel worktree units, ff/merge to main). Delivery: work-unit commits, one branch, governance changes as their own commits. Test runner: `npm test` (Node v24), focused `LC_ALL=C node --import ./test-setup.mjs --import tsx --test <file>`; full gate per AGENTS.md.

## Specs

Source: campaign run `run-ed28973-mvqy1s7l-64c65862` (name-webapp ed28973: 3 commits, 80 files, +1528 −537, tier broad) and the design `/private/tmp/claude-502/-Users-arielyumn-Desktop-TRABAJO-ai-pipeline/f599bf05-d5b3-43ba-9aeb-2e756fa9f02a/scratchpad/design-unavailability-and-impact-walk.md` (§ references below), with the owner's decisions in L3–L5.

- **S1 Adaptive impact walk (design §4; decisions 7, 8).** No global symbol cap cuts the walk. Each node records which seeds reach it. A node whose fan-in exceeds the index's own p99 in-degree (floor and ceiling set by the P0.2 measurement) is recorded as a hub and not expanded; only paths through it stop. The walk runs depth by depth under a count-based cost bound; when it is spent, only seeds whose frontier was still open are `partial`, and their proven pages stand. Route nodes the walk reaches are kept (today dropped at `codegraph-code-graph.adapter.ts:265`). Hub closures are computed in memory per run. One `WalkPolicy` serves the three callers (`structural-signal-port.adapter.ts:18`, `resolve-cross-repo-impact.use-case.ts:27`, the code-graph adapter); 300 survives only as a rendering bound. Absence of reach is claimed only when no seed is partial.
- **S2 Route availability classification (design §3; decisions 1–6 as amended).** A route that redirects or is unavailable during capture is classified deterministically, first match wins, into `change-introduced` (asserted as a use case), `regression-candidate` (recorded signal plus a line in the PR/Issue, `BREAK_NEEDS_HUMAN` on a matching failure, no gate), `environment` (today's behaviour, `E-PRECONDITION`), `pre-existing` and `unexplained` (today's behaviour). `pre-existing` is proven by git and the graph — the route's declaration and its guards are unchanged between the base sha and head and no changed symbol reaches them through a complete walk — or by session consistency (the app's declared login page sends a captured session away). There is NO route-observation ledger, NO `dev.availability` config and NO `dev.clients` profiles (deferred). Missing or partial evidence is `unexplained`, never `pre-existing`. The capture records the navigation facts it lacks (document status, server vs client redirect, whether a session was attached). Flow through the engine per design §3.8: a facts-only Context Pack availability section, a `route-config` reach basis making governed routes direct candidates, the plan check refusing `no-observable-change`/`needs-unavailable-state` drops of a `change-introduced` candidate, a verifiable `availability` review citation, the fix-loop triage, `gateSignals.routeAvailability`, and the PR body listing every `change-introduced` unavailability.
- **S3 No fixed caps that cut grounding or prompt sections.** The Context Pack's per-page `node-cap`/`line-cap` cuts (run: `context_complete` 0.375, 5 of 8 change pages lost content) and the assembler's fixed section cap (run: `reviewer-missing-cases` truncated 8778 → 4000 bytes) are replaced by the window fit rule of prompt-integrity S12 (`ContextBudget`), with the degradation order and what was left out recorded; nothing is cut silently.
- **S4 Reviewer citations.** The reviewer rejected with 6 blocking findings and every one was dropped as uncited (`review_verdict = approved-over-model-rejection`). Find why (contract, prompt, parse, or filter) and fix the root cause transversally, model-agnostic.
- **S5 `run_spec` write refusals.** 9 of 17 `run_spec` calls were refused `no-writes`. Root cause (T4): the seed fixture's DEV-write counter (`config/e2e/fixtures.ts:486-492`) counts every answered mutating request of the browser context to any origin, page-load requests included, so read-only specs spend the share. Fix: count only requests to the app's declared DEV origins; record each counted request (method, origin+pathname) on the ledger and span; a per-flow refusal (`run-spec-capability.ts:206`) counts in `writesRefused`; once a flow's `run_spec` is refused for writes, the lead review does not send it back only to get a `run_spec` pass (execution and the fix loop judge it).
- **S6 Run duration.** The run took 63 min (generation 33, coverage+review 23; one author 1064 s). Explain where the time goes from Tempo/Loki, then optimise, after S1–S5 are correct (owner priority: correct first).
- **S8 Mutants of the change's own code.** A bundle mutant is applied only to an expression whose text appears on the changed source line it maps to (compiler-injected code, e.g. a framework's dev-mode guard, is never mutated), and its re-run runs only the tests that reached the mutated line. Run evidence: 2 of 3 mutants were `ngDevMode → !(ngDevMode)` on lines whose source holds no such expression.
- **S9 Regeneration accepted per spec file.** A regeneration whose acceptance run fails some cases keeps every spec file whose cases all passed and restores only the others (`regeneration-acceptance.ts:146` restores all today); the recount, survivor closure and the "bytes on disk last ran green" rule hold file by file. Run evidence: 2 of 13 failing cases discarded a 968 s branch-case regeneration including an all-green file.
- **S10 Span model attribute.** `invoke_agent qa-lead` spans record `qayaba.config.model` = a model the run did not use; it must be the model the turn ran on.
- **S7 Unrouted coverage findings.** 2 coverage findings were left unrouted ("the file they name seeds no use case of the change"). Determine whether the 300-symbol cut explains them (then S1 fixes them) or fix the cause.
