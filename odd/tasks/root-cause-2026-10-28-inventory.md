Code: main at 4105c582 (working tree clean apart from the untracked `config/benchmarks/suite-snapshots/`). Placement rule: `docs/engine-platform-architecture.md:84-101` (decision table, first yes places the module; more than one yes means split).

## Scope and method

- 37 production modules: the `.ts` files directly in `src/server/` whose name starts with a-k, tests excluded. The 44 test files of the range are not modules; each moves with the module it pins (list at the end). `file-boundary-probe.mjs` and `file-boundary-probe.d.mts` are not `.ts` modules; they move with `file-boundary-check.ts`.
- Importers: a resolver over `src`, `qa-engine`, `scripts`, `packages`, `web/src`, `bin`, `agents`, `client` and the root `boot-guard.mjs` / `test-setup.mjs`, following relative specifiers and the three tsconfig aliases (`@kernel/`, `@contexts/`, `@interface/`), static and dynamic `import()` and `require`. Then a path-literal search of the whole repository (docs, compose files, `bin/`, package scripts, Dockerfile) for each `src/server/<name>.`.
- Dead exports: for each export, a search for any production consumer outside the file.
- "Pinned by" names the existing test at the public seam that step 2 must keep green before and after a move.
