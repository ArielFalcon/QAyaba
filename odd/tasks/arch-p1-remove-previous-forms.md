# Architecture phase 1: Remove previous forms (behavior-neutral)

Objective: no name, file, comment, test title, doc or stored shim refers to a previous form of the architecture (`rewritten`, `legacy`, `bridges`, Codex, dual mode, the `router` event kind, the explorer, `CLAUDE.md`, codebase-memory), and a CI check keeps it that way. Source: `docs/architecture-remediation.md` (plan phase 1, P1.1 to P1.7; closes the Legacy remnants groups Names, Removed-resource names, Dead references, Narrating comments, Dead code, Duplication, Historical docs, Persisted-data shims, plus N5 and N7). Baseline: HEAD `209dca5f` (2026-10-25).
Branch: `fix/failure-observation-conflict` (owner rule: one branch, no PR split). Delivery: work-unit commits (about 400 authored lines each, advisory; a pure rename commit may exceed it); a task whose Risk names a high-risk item ships as its own commit. Runner: `node --import ./test-setup.mjs --import tsx --test <file>` under Node v24.11.0. Phase gate: `npm run previous-forms:check` (S6b) exits 0 and lists only allow-listed hits, with the full gate green (S8).

Reading order for the implementer: S0, then the Tasks list (execution order differs from S numbering), then each S# as you reach its task. Measure with `git grep` (tracked files only). Plain `rg` also walks `.claude/worktrees/` and `.stryker-tmp/`, which hold stale copies of the repo and inflate every count.

## Specs

- **S0: Constraints on every task of this phase.**
  - **Golden rule.** Project-agnostic and model-agnostic. No app-specific branch in `src/` or `qa-engine/`. Nothing names the model in use. Fixes are root-cause and transversal (AGENTS.md, "Golden rule").
  - **Final state only.** No code, name, comment, test title or doc may refer to a previous form of the architecture or to a resource that no longer exists (owner, L1). Comments describe the final state, not the process.
  - **Behavior-neutral.** This phase changes names, deletes dead or removed things and narrows types. Run the differential check on every task: copy the base commit to `mktemp -d` (outside the worktree), run the focused tests there and in the worktree, and compare the pass and fail lists; the only differences allowed are the tests this phase deletes or renames. The deliberate output changes are listed per task (S3 the event kind, S4a three lines of the sidekick brief, S5 the agent-config wire shape, S7 stored-data handling).
  - **Invariants near this phase.** Security boundary (agent read-only on watched repos); no role reads credentials; `opencode serve` never open (S5 touches the supervisor and `agents/opencode.json` neighbors); the agents container never holds the test account (S5 removes `CODEX_EXEC_ENV_PREFIX` text from it); a watched repo cannot configure the agent (S5 removes the Codex half of that sentence); file permissions are the boundary for secrets (S7b touches the API token path and the file-boundary probe); untrusted input through the confined reader (S2 moves files around it); surface integration errors loudly and sanitization (none may be weakened by a rename).
